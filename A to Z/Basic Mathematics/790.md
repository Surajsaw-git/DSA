Your problem is to count how many prime numbers exist in the range from `1` to `n` according to the LeetCode version, where the upper limit `n` is exclusive.

For example, if `n = 10`, we count prime numbers from `1` to `9`.

The answer is `4`, because the prime numbers are `2, 3, 5, 7`.

## 1. What is a prime number?

A prime number is a number greater than `1` that has exactly two positive divisors: `1` and itself.

Examples:

| Number | Divisors   | Prime? |
| ------ | ---------- | ------ |
| 1      | 1          | No     |
| 2      | 1, 2       | Yes    |
| 3      | 1, 3       | Yes    |
| 4      | 1, 2, 4    | No     |
| 5      | 1, 5       | Yes    |
| 6      | 1, 2, 3, 6 | No     |
| 7      | 1, 7       | Yes    |

Notice that `2` is the smallest prime number and the only even prime number.

Why do we need this?

## 7. The outer `for` loop

```
for (int i = 2; i * i < n; i++) {
    if (isPrime[i]) {
        // Mark multiples
    }
}
```

This loop chooses numbers that might be prime and checks their multiples.

Let's understand each part:

- `int i = 2`: start from `2`, the smallest prime number.
- `i * i < n`: continue while the square of `i` is less than `n`.
- `i++`: increase `i` by `1` after each iteration.

Why do we use `i * i < n` instead of `i < n`?

Because we only need to eliminate multiples using factors up to the square root of `n`.

For example, consider `12`:

\\[ 12 = 3 \times 4 = 4 \times 3 \\]

If a number is composite, at least one of its factors must be less than or equal to its square root. Otherwise, both factors would be greater than the square root, and their product would exceed the number.

For `n = 10`, the outer loop behaves as follows:

| `i` | `i * i < 10`      | Action                 |
| --- | ----------------- | ---------------------- |
| 2   | `4 < 10` — true   | Process multiples of 2 |
| 3   | `9 < 10` — true   | Process multiples of 3 |
| 4   | `16 < 10` — false | Stop                   |

Notice that `i = 4` is not processed. We do not need it because all composite numbers below `10` have already been eliminated using smaller prime factors.

The condition could also be written as `i * i < n` for this exclusive upper bound, exactly as in your code.

## 8. Checking `if (isPrime[i])`

```
if (isPrime[i]) {
    for (int j = i * i; j < n; j += i) {
        isPrime[j] = false;
    }
}
```

This checks whether `i` is still marked as prime.

If `isPrime[i]` is `true`, we eliminate its multiples.

If it is `false`, it means `i` was already identified as a composite number, so we can skip it.

For example, `4` is a multiple of `2`, so when we reach `i = 4`, `isPrime[4]` is already `false`.

We do not need to use `4` to eliminate multiples again.

This avoids unnecessary work.

## 9. The inner `for` loop — the heart of the algorithm

```
for (int j = i * i; j < n; j += i) {
    isPrime[j] = false;
}
```

This loop marks the multiples of `i` as not prime.

Let's understand each part:

- `int j = i * i`: start from the square of `i`.
- `j < n`: do not go beyond the exclusive upper bound.
- `j += i`: move to the next multiple of `i`.
- `isPrime[j] = false`: mark that number as not prime.

### Why does `j` start at `i * i`?

Suppose `i = 3`.

Its multiples are:

```
3, 6, 9, 12, 15, ...
```

But `3` itself is prime. Also, `6` has already been eliminated as a multiple of `2`.

Starting at `3 * 3 = 9` avoids repeating work.

In general, multiples smaller than \\(i^2\\) have already been handled by smaller factors.

### Let's trace the loop for `n = 10`

First, `i = 2`.

The inner loop begins with:

```
int j = 2 * 2;
```

So `j = 4`.

Then it repeatedly adds `2`.

| `j` | Operation            | Result       |
| --- | -------------------- | ------------ |
| 4   | `isPrime[4] = false` | 4 eliminated |
| 6   | `isPrime[6] = false` | 6 eliminated |
| 8   | `isPrime[8] = false` | 8 eliminated |

The next value is `j = 10`. Since `10 < 10` is false, the loop stops.

Now the vector looks like this:

| Number | `isPrime` |
| ------ | --------- |
| 0      | `false`   |
| 1      | `false`   |
| 2      | `true`    |
| 3      | `true`    |
| 4      | `false`   |
| 5      | `true`    |
| 6      | `false`   |
| 7      | `true`    |
| 8      | `false`   |
| 9      | `true`    |

Next, the outer loop advances to `i = 3`.

Because `isPrime[3]` is still `true`, we process its multiples:

```
j = 3 * 3 = 9
```

We execute:

```
isPrime[9] = false;
```

Then `j` becomes `12`, and the inner loop stops because `12 < 10` is false.

The final vector is:

| Number | `isPrime` |
| ------ | --------- |
| 0      | `false`   |
| 1      | `false`   |
| 2      | `true`    |
| 3      | `true`    |
| 4      | `false`   |
| 5      | `true`    |
| 6      | `false`   |
| 7      | `true`    |
| 8      | `false`   |
| 9      | `false`   |

The numbers that remain `true` are `2, 3, 5, 7`.

## 10. Counting the prime numbers

After the sieve finishes, your code executes:

```

for (int i = 2; i < n; i++) {
    if (isPrime[i]) {
        primecount++;
    }
}

return primecount;
```

Let's break it down.

### Step A: Initialize the counter

```
int primecount = 0;
```

We start with zero because we have not counted any prime numbers yet.

### Step B: Visit each number

```
for (int i = 2; i < n; i++)
```

For `n = 10`, this visits:

```
2, 3, 4, 5, 6, 7, 8, 9
```

We start at `2` because `0` and `1` are not prime.

### Step C: Count only prime numbers

```
if (isPrime[i]) {
    primecount++;
}
```

Whenever a value is `true`, increase the counter by one.

| `i` | `isPrime[i]` | `primecount` |

| 8   | `false`      | 4            |

Finally:


The function returns `4`.

## 12. Time and space complexity

### Time complexity: \\(O(n\log\log n)\\)

The sieve eliminates multiples of each prime number. Although there are nested loops, the inner loop does not run `n` times for every `i`.

The total work of eliminating multiples is approximately:

\\[ n\left(\frac12+\frac13+\frac15+\cdots\right) \\]

where the sum is over prime numbers. This leads to the well-known Sieve of Eratosthenes complexity of \\(O(n\log\log n)\\).

The final counting loop takes \\(O(n)\\) time, which does not change the overall complexity.

### Space complexity: \\(O(n)\\)

The vector stores one Boolean entry for every number from `0` to `n - 1`.

Therefore, its space requirement grows linearly with `n`.
